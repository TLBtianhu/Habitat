# SPEC-05 身份与槽（冻结候选）

> 版本：v0.1 草案 · 状态：待审
> 上位律：`READING.md` A2/A3、D4；来源 MEMORY L91（单调发号白赚无环）、L148/L393（id 与地址对偶）、L395（地址单增律）
> 一句话：**身份是 id，位置是槽；换身体不换灵魂。**

---

## 1. 六个 id 空间

| 空间 | 用途 | 发号者 | 生命周期 |
|---|---|---|---|
| `EventId` | 事件身份 | 输入队列 | 永久 |
| `CommandId` | 命令幂等键（ulid） | 泵 | 永久 |
| `ArtifactId` | 技能/插件产物 | 构建器 | 永久 |
| `SceneId` | 场景 | 舞台 | 随声明 |
| `ActorId` | 平台用户（跨场次稳定） | 适配器映射 | 跨会话 |
| `Generation` | 代数（激活次数） | 运行时 | 单调递增 |

**D-1** 每工作区一个发号器；**严禁**多进程各自发号（会撞号）。
**D-2** id **必须**单调递增、**永不回收**。回收的是驻留（内存/进程），不是身份。
**D-3** id **必须**可序列化进存档；重载后同一对象仍是同一 id。

---

## 2. id 与 name 分家

| | id | name |
|---|---|---|
| 何时定 | 运行期创生 | 分发期确定 |
| 唯一性 | 全局单调 | 仓库/单件制 |
| 谁用 | 引用、存档、日志 | 人读、`op` 字段、清单 |
| 可变 | 不可变 | 可改（改的是显示） |

**D-4** 跨会话引用一律用 id；**严禁**用路径或名字当身份（路径会变，名字会撞）。
**D-5** 名字解析成 id 是**装配期**的事；运行期不查名字（D4：树只在装配期）。

---

## 3. 槽（运行实例）

```
ArtifactId chop-tree#7f3a        ← 身份，永久
   ├─ slot 1.2.0 → worker A      ← 槽，可换
   ├─ slot 1.3.0 → worker B      ← 预热中
   └─ slot 1.1.0 → 已释放
live.json: { "chop-tree": "1.2.0@sha256:ab12…" }   ← id → 槽 的解析表
```

**D-6** 切换 = **原子替换解析表**；**严禁**原地修改正在运行的实例。
**D-7** 状态挂在 **id** 上，不挂在槽上；新槽启动只做**兼容性校验**，不做"状态迁移"。
**D-8** 回滚 = 表指回旧槽 + 恢复该槽的状态快照，**< 1s**。
**D-9** 槽释放**必须**走 disposer（注册的撤销动作），**严禁**只丢引用。

---

## 4. 无环：白赚的结构

**D-10** 引用**只能**指向 id 更小的对象（创建即定号）。
**D-11** 因此依赖图**天然无环**，拓扑序 = id 序；**严禁**写环检测代码（多余且会掩盖设计错误）。
**D-12** 若出现"需要引用更大的 id"，说明设计错了，**必须**改成两阶段（先建再绑）。

---

## 5. 代数

**D-13** `Generation` 每次成功激活 +1，**只增不减**。
**D-14** 代数**必须**进命令日志与舞台角标（观众可见"第 N 代"）。
**D-15** 回滚**不减少**代数（回滚也是一代，记 `rollback` 原因）。

---

## 6. 持久化

**D-16** 存档只存 id 与引用，不存指针/路径/临时序号。
**D-17** 重载后 id 不变、槽可变；观众看到的"还是她"由 id 保证。
**D-18** 跨版本 id **必须**稳定；删 id = 删除身份，**必须**走 ADR。

---

## 7. 可执行不变量

| 编号 | 不变量 | 验证 |
|---|---|---|
| I1 | id 单调且不重复（10⁶ 次发号） | 属性测试 |
| I2 | 引用必指向更小 id | 属性测试 + lint |
| I3 | 解析表替换是原子的（并发读不出现半态） | 并发测试 |
| I4 | 回滚 < 1s 且 id 不变 | 集成测试 |
| I5 | 槽释放必调 disposer（无泄漏定时器/监听器） | 泄漏测试（重载 100 次） |
| I6 | 存档不含路径/指针 | schema 测试 |
| I7 | 代数单调 | 单元测试 |

---

## 8. 待拍板

1. **id 编码**：建议 `u64` 单调 + 展示用 `0x…`；不用 uuid（不可排序、不可压缩）。
2. **ActorId 是否跨平台统一**：建议**不统一**（B站用户 ≠ 抖音用户），只在需要时人工合并。
3. **`SceneId` 是否单调**：建议**不单调**（场景是声明，不是创生），用名字即可——它不参与引用环。
