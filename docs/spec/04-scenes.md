# SPEC-04 投影与场景协议（冻结候选）

> 版本：v0.1 草案 · 状态：待审
> 上位律：`READING.md` A1（声明唯一真源）、D6（自由来自约束）、B3（勤快只在出口）
> 一句话：**场景只声明"放什么"，不声明"怎么画"；画面是状态的投影，不是录屏。**

---

## 1. 目的

定义舞台如何把"她此刻的状态"渲染成一帧画面，以及三个场景各自的边界。

**不**定义：动作（SPEC-02）、相位（SPEC-03）、热更（SPEC-06）。

---

## 2. 两个函数，别的一律不许

```ts
// 每帧调用，必须幂等、无副作用
present(state: StageState, t: FrameNo): FrameTree

// 输入翻译：物理事件 → 命令（不直接改状态）
translate(input: InputEvent): Command | null
```

**S-1** 场景**严禁**在 `present` 里改状态、发命令、写文件、发网络请求。`present` 是纯函数。
**S-2** 场景**严禁**直接读事件队列；它只能读**状态投影**（`StageState`）。
**S-3** 跨帧状态（动画进度、粒子、渐变）**必须**住 `ctx` 并跨帧续存；**严禁**在帧边界清零（否则画面会"爆音"）。

---

## 3. 场景声明：提示，不是命令

```ts
type SceneManifest = {
  id: SceneId;
  kind: 'desktop' | 'code' | 'world' | 'standby' | 'ending';
  capabilities: string[];       // 依赖的能力，缺则不加载
  layoutHints: LayoutHint[];    // "适合怎么展示"，不是"必须画成什么样"
  bindings: Binding[];          // 状态路径 → 槽位
  predicates: Predicate[];      // 可见性谓词
};
```

**S-4** `layoutHints` 只允许表达"适合居左/需要 16:9/需要高对比"这类**偏好**；**严禁**携带坐标、颜色、字体、绘制指令。
**S-5** 场景**严禁**包含循环、条件分支、自定义绘制。要"能写逻辑"的应该是插件，不是场景（D6）。
**S-6** 场景变更**必须**是声明变更（改 manifest），**严禁**运行时拼装视图树。

---

## 4. 三个场景

| 场景 | 数据来源 | 渲染 | 已知限制 |
|---|---|---|---|
| `desktop` | 沙箱屏幕（x11grab → 低延迟流） | `<video>` 贴图 | 唯一使用像素的场景；带宽最高 |
| `code` | 文件变更 / PTY 字节 / 测试结果 | Monaco + xterm **重渲染** | 不显示宿主 IDE；字号由舞台定 |
| `world` | mineflayer 世界状态 | prismarine-viewer（WebGL） | 无光影；限 30fps |

**S-7** `desktop` **必须**是唯一"看着像录屏"的场景，且它只捕获**沙箱**屏幕，永不捕获宿主。
**S-8** `code` **严禁**用屏幕捕获实现。它渲染的是**事件**（谁在第几行敲了什么），所以字号、聚焦、diff 全部可导演。
**S-9** `world` **必须**支持"脏重算"：世界没变就不重绘；只有编码器按帧率勤快（B3）。

## 5. 画面构成（1920×1080，六层）

| 层 | 内容 | 更新频率 | 数据 |
|---|---|---|---|
| L0 | 背景（房间/海底，慢动画） | 30fps | 声明 |
| L1 | 主画面（当前场景的 surface） | 30fps | 场景 |
| L2 | 角色（Q 版，口型/表情/呼吸） | 30fps | 状态（情绪/口型包络） |
| L3 | 文字（字幕、弹幕、礼物、ticker） | 事件驱动 | 事件流（只读） |
| L4 | 常驻（标题、在线、AI 标识、状态角标） | 低频 | 状态位 |
| L5 | 转场卡（切换/降级/重启时） | 事件驱动 | 相位 |

**S-10** L2 角色层**严禁**遮挡 L1 的关键区域超过 20%（观众要看她在干什么）。
**S-11** L5 转场卡**必须**在场景切换时先于新场景出现；新场景首帧就绪后才撤卡——这是"不黑屏、不定格"的实现方式。

---

## 6. 转场协议

**S-12** 切场景流程固定为：`上卡 → 等新场景首帧 → 交叉淡化 → 撤卡`。
**S-13** 新场景 3 秒内未出首帧：**必须**留卡 + 状态角标红 + 发 `system{ sub: 'scene_timeout' }`，**严禁**无限等待。
**S-14** 转场**必须**可被打断（人工接管/降级），打断时直接切待机卡。

---

## 7. 状态角标（观众可见的诚实层）

**S-15** 角标**必须**至少显示：`streaming`、`controller`、`degraded`、`scene`。
**S-16** `controller = human` **必须**有明确视觉（如"人工接管中"），且不可被场景样式覆盖。
**S-17** `degraded` **必须**显示为"她那边有点事"，**严禁**显示内部技术原因（编码器/沙箱细节不外泄）。

---

## 8. 性能预算

| 项 | 预算 | 超了怎么办 |
|---|---|---|
| 舞台渲染 | ≤ 8ms/帧（1080p30） | 降背景动画帧率，不降角色帧率 |
| 世界视图 | ≤ 20ms/帧 | 降渲染距离、降 30→20fps |
| 编码 | NVENC，GPU 侧 | 720p30 兜底 |
| 显存 | < 2.5GB（本机 4GB） | 顺序加载场景，不并行预热 |

**S-18** 三个场景**严禁**同时启用；同一时刻只有一个 surface 在跑（P-3 的算力侧推论）。

## 9. 可执行不变量

| 编号 | 不变量 | 验证 |
|---|---|---|
| I1 | `present` 纯函数（同输入同输出） | 快照测试 |
| I2 | 场景 manifest 中无绘制指令字段 | schema 校验 |
| I3 | 切场景 P95 ≤ 1s，黑场帧数 = 0 | 端到端 |
| I4 | 新场景超时 3s 必上红标 | 虚拟时钟 |
| I5 | `code` 场景不产生屏幕捕获 | 静态检查（无 grab 依赖） |
| I6 | 角标四项齐全 | 视觉快照断言 |
| I7 | 显存峰值 < 2.5GB | 压测 |

## 10. 待拍板

1. **代码镜头是否逐字符"打字"**：建议**是**，但速度可调（0.5×–2×），且她思考时显示"正在想"而非空屏。
2. **角色口径**：建议 1080p 下角色高度占画面 35%，竖屏适配另说。
3. **弹幕区位置**：建议底部 1/5，且不遮挡字幕。
