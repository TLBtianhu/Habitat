# SPEC-06 沙箱能力清单与热更（冻结候选）

> 版本：v0.1 草案 · 状态：待审
> 上位律：`READING.md` C1/C2/C3/C4、D5；`RUNTIME.md` 第 3–4 节
> 一句话：**插件能做什么，由能力清单决定；沙箱能隔离什么，写在纸上，不靠形容词。**

---

## 1. 能力清单（闭集，按域）

| 域 | 能力 | 副作用 |
|---|---|---|
| `mc.` | `moveTo` `dig` `place` `look` `inventory` | 改世界 |
| `voice.` | `say` `stop` | 出声音 |
| `chat.` | `send` `read`（只读队列） | 发弹幕 |
| `stage.` | `switch` `idle` `overlay` | 改画面 |
| `media.` | `play` `stop` `volume` | 放媒体 |
| `stream.` | `start` `stop` `status` | 对外可见 |
| `system.` | `handover` `quota` | 改控制权 |
| `fs.` | `readArtifact` `writeTemp`（**仅临时区**） | 本机 IO |
| `net.` | `http`（仅白名单域） | 出网 |
| `exec.` | `runTest`（**仅一次性实例**） | 执行代码 |

**K-1** 能力名是闭集；插件 manifest 只能**申请**，不能定义新能力。
**K-2** 未声明的能力**必须**在调用时被 broker 拒绝，并记录 `capability_denied`。
**K-3** `fs.write` 到非临时区、`net` 到非白名单、`exec` 到非一次性实例，**一律**拒绝。

**K-4** manifest 缺任一必填项**必须**拒载。
**K-5** 能力申请**必须**在安装时人工可见（首次安装弹一次"它要这些能力"，之后静默）。

## 3. 沙箱边界（诚实清单，照 MEMORY L1344 的写法）

### 能隔离

1. 实例身份与本地状态（id 稳定、槽可换）；
2. 声明与凭证分离（**沙箱内不存任何 cookie/key**）；
3. 结构性稳定（schema、单写者、事务、撤销、不变量）；
4. 显示策略互不污染（场景各自渲染）；
5. 逻辑生命周期（可停止、重启、卸载技能）。

### 不能隔离

1. **崩溃域**：同一进程内崩溃会拖垮全体 → 所以呈现与推流必须在独立进程；
2. **资源与调度**：GPU、显存、全局注册表可能暗串行；
3. **不可信代码**：沙箱不是执行引擎，真隔离靠 OS 边界（WSL/VM），不靠 `vm` 模块；
4. **权限**：插件不能给自己授权，权威在 broker；
5. **开发者模式**：她的自改是功能政策，不是安全措施（C2）。

**K-6** 每条"不能隔离"**必须**在 README 里如实写出；**严禁**用"VM/沙箱"这类词暗示它做了它没做的事。

## 4. 凭证：不动，调用移动

**K-7** 平台 cookie、TTS key、LLM key **必须**住在宿主侧凭据服务；沙箱内 `grep -r "sk-"` **必须**为空（P1 验收项）。
**K-8** 需要凭证的调用**必须**由 broker 代发，沙箱只收到结果，不收到凭证。
**K-9** 凭证**严禁**进日志、进命令参数、进事件信封。

> 这条对应 MEMORY L25：SSH 密钥是范本——公钥给出去，私钥永不出本机，秘密不过线。

## 5. 热更四级（与 `RUNTIME.md` 一致）

| 级 | 对象 | 手段 | 时延 |
|---|---|---|---|
| L1 | 技能（JS/TS） | 蓝绿槽 + 原子表替换 | < 300ms |
| L2 | 数据（datapack/配方/函数） | `/reload` + 失败回退 | 1–5s |
| L3 | Java 模组 | 编译 → 一次性实例验证 → **重启服务端**（不是她的身体） | 20–40s |

> **2026-10-31 修订**（依据 `docs/research/mc-modding.md`）：她的身体是无头浏览器 + mineflayer bot，**没有游戏客户端**，
> 所以 L3 只做**服务端模组**；重启窗口是 MC 服务器，bot 自动重连，舞台不受影响。
> 版本须与 bot 协议对齐：当前 mineflayer 上限 **MC 26.1**（教程示例是 26.3，方法照用、版本重钉）。
| L4 | 核心 | 人工发布，**她无权** | —— |

**K-10** L3 **必须**走"转场卡 + 重启 + 重连"，直播不中断；一场上限 **2 次**。
**K-11** L1 切换**必须**有观察窗口（60s）与自动回滚；回滚 < 1s。
**K-12** 任何热更**严禁**清空跨帧状态（B4 的推论：那会"爆音"）。

## 6. 可删性（fork 者敢试的前提）

**K-13** 自迭代层（artifact 构建、热更、影子模式）**必须**整体挂在 `feature: self-iteration` 后面，一个开关关掉后系统仍能完整开播。
**K-14** 关掉后**严禁**留下死代码路径或半残 UI（假按钮规则，L1200）。
**K-15** 能力清单在关闭状态下**必须**只保留 `mc/voice/chat/stage/media/stream`（无 `exec/net/fs`）。

## 7. 可执行不变量

| 编号 | 不变量 | 验证 |
|---|---|---|
| I1 | 未声明能力调用必拒 | 单元测试 |
| I2 | 沙箱内无凭证（grep 为空） | 隔离测试 |
| I3 | manifest 缺项必拒载 | 单元测试 |
| I4 | 关闭 self-iteration 后完整开播 | 端到端冒烟 |
| I5 | L1 回滚 < 1s 且状态不回退 | 集成测试 |
| I6 | 重载 100 次无泄漏（定时器/监听器） | 泄漏测试 |
| I7 | 缺失能力在角标可见 | 视觉断言 |
| I8 | `exec` 只能指向一次性实例 | 静态检查 + 运行时校验 |
