# SPEC-03 模式机与不变量（冻结候选）

> 版本：v0.1 草案 · 状态：待审
> 上位律：`READING.md` D2（动作只活在泵里）、B4（播放头永不撒谎）、B5（调度只能变慢不能变错）
> 接缝：[SPEC-02 命令](02-commands.md) 的 `wrong_phase` 由本规格判定
> 一句话：**玩的时候不写，写的时候不玩；出事只降级，不假装。**

---

## 1. 相位集合（六个）

| 相位 | 她在干什么 | 观众看得见？ | 世界可写？ |
|---|---|---|---|
| `BOOT` | 自检、加载能力 | 开机动画 | 否 |
| `OFFLINE` | **不播但活着**：整理记忆、核对承诺、准备下一场 | **看不见** | 否 |
| `IDLE` | 在播间隙的待机（窗口已开、还没进内容） | 待机舞台 | 否 |
| `PLAY` | 玩 MC / 逛网页 / 放视频 | 全屏实况 | **是**（唯一） |
| `CODE` | 写代码、改插件、跑测试 | 全屏代码镜头 | **否**（只读） |
| `VERIFY` | 上线新产物后的验证段 | 世界 + 新能力标签 | **是**（受限于新产物） |
| `DEGRADED` | 出事兜底 | 待机卡 + 音频 | 否 |
| `ENDING` | 谢幕、写交接、下播 | 谢幕页 | 否 |

**`IDLE` 与 `OFFLINE` 的分界**：`IDLE` 里她还在场（观众看得见待机舞台），`OFFLINE` 里观众看不见她。两者的规则完全不同，**严禁**合并。

**P-1** 相位是**单值**的，任何时刻只有一个。控制权、推流状态、可见性是**正交状态位**，不在相位里（见 §6）。
**P-2** 不存在 `PAUSED` 相位。暂停 = 控制权交给人的一个状态位，画面继续。

---

## 2. 硬不变量

**P-3** `PLAY` 与 `CODE` **严禁**同时处于"可操作"状态。这条是整套设计的承重墙：它同时保证安全（改的时候不跑）、画面（全屏不抢）、算力（同一时刻只有一个重子系统）。
**P-4** 进入 `CODE` 前**必须**依次完成：quiesce → 存档 → 挂机/登出 → 测试实例就绪。任一步失败**必须**留在 `PLAY`。
**P-5** 任何相位的失败，**必须**回退到**上一个成功相位**，**严禁**直接跳 `IDLE`（那等于把直播搞成"人没了"）。
**P-6** `DEGRADED` **可**从任意相位进入；恢复时**必须**回到**进入前的相位**，不许"恢复成 IDLE 重新开始"。
**P-7** `ENDING` 是唯一允许她在无人指令下停止推流的相位，且**必须**先谢幕再停流。

## 3. 转换表

| From → To | 守卫 | 动作 | 失败回退 |
|---|---|---|---|
| `BOOT → IDLE` | 配置、能力清单、编码器自检全过 | 加载舞台、连平台 | `DEGRADED` |
| `IDLE → PLAY` | bot 可用 ∧ 世界可达 ∧ 编码器就绪 | 建立世界会话、切 `WORLD` 场景 | `IDLE` |
| `PLAY → CODE` | quiesce 成功 ∧ 存档成功 ∧ 挂机成功 ∧ 测试实例就绪 | 切 `CODE` 场景、世界置只读 | `PLAY` |
| `CODE → VERIFY` | 产物过测试 ∧ 部署成功 | 切回世界、打"新能力"标 | `CODE` |
| `VERIFY → PLAY` | 新能力冒烟通过 ∧ 无异常 3 分钟 | 摘标、恢复正常调度 | `VERIFY` 或回 `CODE` |
| `CODE → PLAY` | —— | 放弃本次修改、恢复世界写权限 | —— |
| `任意 → DEGRADED` | 编码器断 / 沙箱挂 / 世界掉线 / 落盘失败 | 切待机卡 + 音频床 + 状态角标 | —— |
| `DEGRADED → 原相位` | 健康检查恢复 ∧ 对账通过 | 重建会话、恢复场景 | 留在 `DEGRADED` |
| `IDLE → OFFLINE` | 播出窗口结束 ∧ 无待完成承诺 | 保存待机状态 | `IDLE` |
| `任意 → ENDING` | 人工指令 ∨（她 ∧ 满足下播谓词 §7.5） | 谢幕、停流 | —— |
| `ENDING → OFFLINE` | 谢幕完成 ∧ 推流停止 ∧ **`session.json` 已写** | 归档本场、转入离线 | 留在 `ENDING` |
| `OFFLINE → IDLE` | 播出窗口开启 ∨ 人工点火 | 读交接、读承诺账本、预热能力 | —— |

**P-8** CPU 里不存"上一相位"这种隐式状态；**必须**显式记录 `lastStablePhase`，崩溃重启后据此恢复。

## 4. quiesce 协议（进 CODE 的唯一门）

五步，任一步失败则整体失败：

1. **关门**：闸门停止接受新意图（事件继续入队，只是不产生命令）；
2. **等在途**：等待在途命令完成，上限 **3 秒**；
3. **取消**：超时命令逐个 cancel，**必须**记录 `cancelled`；
4. **存档**：写 `world-state.json`（位置、背包、当前任务、进度、当天已做的事）；
5. **挂机或登出**：v1 采用**挂机**——走到安全点、停止移动、拒绝一切操作；世界服务端继续跑。

**P-9** quiesce 期间**严禁**接受新命令；来一个拒一个，理由 `wrong_phase`。
**P-10** 挂机状态**必须**对观众可见（角色坐/站 + 场景标签），不许看起来"她还在动"。

---

## 5. CODE 相位的隔离要求

**P-11** CODE 相位中的编译、测试、试跑**必须**在**一次性实例**（独立世界/独立容器）里跑；**严禁**碰直播世界。
**P-12** 直播世界在 CODE 相位**必须**是只读的（bot 无写权限，或干脆不在线）。
**P-13** 网络出口在 CODE 相位**必须**受限（只允许包仓库与文档站），防止把"写代码"变成"随便逛"。

## 6. 正交状态位（不在相位里）

对应 MEMORY L1186 的五状态分家。**"在线"不是一个布尔。**

| 状态位 | 取值 | 语义 |
|---|---|---|
| `streaming` | bool | 是否在向平台推流 |
| `visible` | bool | 观众能否看见画面（可推流但黑场） |
| `controller` | `agent` \| `human` | **谁在控制**（接管） |
| `scene` | `SceneId` | 当前场景（与相位可不同：PLAY 里也能切 DESKTOP） |
| `degraded` | `null \| { reason }` | 降级原因 |

**P-14** `controller = human` 时，agent 的一切命令**必须**被拒，理由 `human_control`（对 SPEC-02 拒绝原因的补充）。
**P-15** 接管**必须**对观众可见（角标 + 一句说明），**严禁**悄悄发生。
**P-16** 接管不是关播：`streaming` 与 `visible` 在接管期间保持不变。

---

## 7. DEGRADED 语义

**P-17** 进入 `DEGRADED` 的**必须**是"机制判定"，不是"情绪判定"：编码器连续 5 秒无输出、沙箱心跳丢失 10 秒、世界断开 10 秒、落盘失败、连续 3 次命令失败。
**P-18** `DEGRADED` 期间**必须**播待机卡 + 音频床；**严禁**定格最后一帧（播放头永不撒谎）。
**P-19** 恢复**必须**先对账：读世界状态、比对 `world-state.json`、决定"原地续"还是"回存档点"。对账不清则留在 `DEGRADED`。
**P-20** 进入与离开 `DEGRADED` 都**必须**写事件（`system{ sub: 'degraded_enter' | 'degraded_exit' }`），并在状态角标显示。

## 7.5 下播谓词与场次交接（ADR-003）

**P-27** 她自主下播**必须**同时满足：

```
canEnd = promisesCleared()          // 承诺清空，或已明确结转
       ∧ duration >= 20min          // 下限：不许一开播就走
       ∧ (goalDone() ∨ idleDensity < θ 持续 15min ∨ duration >= 6h)
       ∧ NOT blockingOnHardTask()   // 不许因为难而走
```

**P-28** 卡住时下播**必须**先说明：卡在哪、下次怎么继续。**卡住是内容，跑掉不是。**
**P-29** `ENDING → OFFLINE` 前**必须**写 `session.json`（完成项 / 承诺 / 未完成与下一步 / 代数）；写不出则**不得**离开 `ENDING`。
**P-30** 下一场开场**必须**读交接，并**至少兑现一件**承诺；承诺账本 append-only，**严禁**删除。
**P-31** 未兑现承诺跨 2 场 → 状态角标红标，且她**必须**在直播里说明；超过 7 天自动转入"欠账"降级处理。

## 8. 与她的事件队列的关系

**P-21** `CODE` 相位期间事件照常入队（SPEC-01 §7），但**严禁**触发模型调用。
**P-22** 回到 `PLAY` 时，积压 > 5 分钟**必须**折叠成一条 `system{ sub: 'backlog_summary' }`；**严禁**逐条重放（那会让观众看到 40 分钟前的弹幕）。
**P-23** `DEGRADED` 期间事件继续入队但**不消费**；恢复后同样走折叠规则。

---

## 9. 崩溃恢复

**P-24** 崩溃重启后，**必须**先读 `lastStablePhase` 与 `world-state.json` 再决定从哪继续。
**P-25** 世界状态以**服务端为准**：bot 重连后先读真实状态，与存档比对；不一致以真实为准，并把差异写进事件（`system{ sub: 'state_drift' }`）。
**P-26** **严禁**"假装没崩过"——恢复本身就是内容，可以说出来。

## 10. 可执行不变量

| 编号 | 不变量 | 验证方式 |
|---|---|---|
| I1 | `PLAY` 与 `CODE` 永不共存 | 状态机穷举测试 |
| I2 | 进 `CODE` 必有存档记录 | 日志断言（无存档不许进） |
| I3 | quiesce 超时必产生 `cancelled` | 虚拟时钟测试 |
| I4 | `DEGRADED` 恢复必回原相位 | 属性测试（任意起点） |
| I5 | `controller=human` 时命令全拒 | 集成测试 |
| I6 | 相位切换 P95 ≤ 5s 且不黑屏 | 端到端（转场卡兜底） |
| I7 | 崩溃重启必先对账 | 故障注入测试 |
| I8 | 连续 3 次失败必进 `DEGRADED` | 故障注入测试 |
| I9 | `ENDING` 必先谢幕再停流 | 顺序断言 |
| I10 | 相位日志可重放且结果一致 | 确定性测试 |
| I11 | 无 `session.json` 不得离开 `ENDING` | 状态机测试 |
| I12 | 自主下播必满足 §7.5 谓词（含"非卡住"） | 属性测试 + 反例用例 |
| I13 | 承诺账本只增不删 | 日志不可变测试 |

## 11. 待拍板（三处）

1. **挂机还是登出**：v1 建议挂机（观感好、实现简单），安全等价——她此刻没有任何操作权限。
2. **`ENDING` 谁触发**：建议她可以在"播够时长且无未完成承诺"时自主下播，但必须提前 30 秒报倒计时。
3. **`DEGRADED` 的观众文案**：建议不写技术原因（"编码器断流"），只写"她那边有点事，等一下"——诚实但不暴露内部。
