# SurfCore 调研：可借鉴的身份、记忆与主动性设计

> 2026-11-01 · 项目：`Mieksido/surfcore`（313★，MIT）

## 它是什么

一个 DSH 插件 + 独立桥接进程的系统：让 agent 在 QQ 里当群友、在 B站当用户、有记忆、有作息、有桌宠分身。
它不是"把大模型接进 QQ"，而是给模型一个**身份**。

## 值得学的六件事

### 1. 记忆：会遗忘的工作记忆 + 永不遗忘的档案

- 进提示词的是**会衰减的记忆卡**；
- 另有**永不遗忘的全量卡**只存档，不直接塞满上下文。

**对 Habitat**：我们的长期记忆也应分两层：工作记忆（近期、可衰减）与档案记忆（长期、可检索）。这比单纯"记住一切"更接近真人。

### 2. 主动性：不只是被 @ 才说话

- 安静时段会自己提炼"想弄明白/想做点什么"，主动分享或索取；
- 有作息、每日额度、偏好，避免刷屏。

**对 Habitat**：AgentLoop 不应只响应事件，应有 quiet-time initiative：定期回顾承诺、世界状态、想做的小事，并受额度与节奏约束。

### 3. 安全边界：owner、白名单、最小暴露

- `ownerQQ` 只认管理员；
- `allow.private/groups` 白名单，**空 = 不响应**；
- 控制台只监听本机，不做多用户。

**对 Habitat**：QQ/直播/陌生服都需要白名单与 scope；默认不响应陌生来源，身份中心只在本机绑定。

### 4. 两进程分工：DSH 插件与独立桥接

- 插件负责人设、设置、记忆、桌宠接口；
- 桥接负责 QQ 收发、会话映射、控制台、安全闸门。

**对 Habitat**：AgentLoop 与客户端进程分离（QQ backend、MC client、Display Server）正好对应。客户端不该被 DSH 的工具调用直接"吞掉"。

### 5. 安装与诊断：一键安装、设置页、故障表

- `setup-dsh.mjs` 幂等安装；
- 设置页 14 个标签，配置与诊断集中；
- 常见故障有明确原因与处理。

**对 Habitat**：分发时要有**安装验收页**（诊断、连通性、白名单、路径检查），而不是只给 README。

### 6. 桌宠是另一种呈现出口

- 桌宠不是直播客户端的一部分，而是另一个可选分身。

**对 Habitat**：Live2D/Q版形象也只是 Display Server 的可选 overlay，QQ 屏幕共享、直播、桌宠可以共用形象但不必绑定。

## 不该照搬的

- Windows 专用安装路径与 SnowLuma 注入式 QQ 运行时：我们要的是 WSL 原生、独立协议后端；
- 它的人人自扫门前雪配置方式：我们要尽量 manifest 化、安装器化；
- 它的"记忆卡格式"本身：只借结构，不直接复用实现。

## 下一步采用

1. 在 AgentLoop 加**记忆分层**：工作记忆（衰减）与档案记忆（检索）；
2. 加 **quiet-time initiative**：低活动期的自主小任务与额度控制；
3. 把 QQ/B站/陌生服都纳入**白名单与 scope**；
4. 做一个**诊断式安装验收页**；
5. 保持 Display/形象/桌宠为可选 overlay，不与直播绑定。
