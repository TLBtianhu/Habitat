# 世界、会话与开播：三条互不相干的轴

> 2026-10-31 · 起因：「她玩游戏 / 开房间 / 你用自己的号联机 / 她开不开播」到底是几件事？
> 结论：**三件事。各自可选，互不绑定。**

---

## 1. 三条轴

| 轴 | 是什么 | 取值 | 谁拥有 |
|---|---|---|---|
| **A 认知** | 她的身份、记忆、承诺、技能、节目单 | 始终在跑（可休眠） | **她的系统**（Authority） |
| **B 世界** | 她此刻在哪个游戏/房间/地图里 | `worldId` 或 `none` | **游戏服务端**（外部服务） |
| **C 播出** | 观众能不能看见 | `streaming` / `visible` | **出口**（Renderer/Outlet） |

三条轴**正交**：

| A 认知 | B 世界 | C 播出 | 形态 |
|---|---|---|---|
| ✅ | ✅ | ✅ | 直播她玩游戏（默认） |
| ✅ | ✅ | ❌ | 她自己在玩（或和你联机），不播 |
| ✅ | ❌ | ✅ | 直播她写代码/聊天 |
| ✅ | ❌ | ❌ | **高级群聊机器人** |
| ❌ | — | — | 整机停（不推荐存在） |

**这解释了"不让她开播就约等于群聊机器人"**：认知不变，只是把 C 关掉——Renderer 与 Outlet 空转，`streaming=false`。

---

## 2. 游戏服务端 ≠ 她的决策系统

这是必须钉死的一条：

| | 游戏服务端 | 她的系统 |
|---|---|---|
| 裁决什么 | 世界：方块、实体、伤害、时间 | 她自己：说什么、做什么、答应谁 |
| 谁拥有 | Mojang/服主/你 | 我们 |
| 关系 | **她连过去的服务**（就像连一个网站） | **客户端**（bot） |
| 挂了会怎样 | 世界暂停，存档还在；她掉线 | 她停止思考；世界照跑 |

**它们是两个进程、两个真源、通过 MC 协议对话。** 她的系统不应该"拥有"世界，也不应该被某一个世界绑住。

之前把服务端搬到宿主是为了修 V1（可访问性），但**它只是"本地可选服务端之一"，不是她的一部分**。

---

## 3. 启动器：World Provider

她要能像玩家一样挑房间。设计成与 `WorkerProvider` 同构的一层：

```jsonc
// worlds.json —— 世界登记表（她可读、人可改）
{
  "worlds": [
    { "id": "home",       "kind": "local",  "address": "127.0.0.1:25565", "version": "1.21.4",
      "auth": "offline",  "note": "自己开的世界" },
    { "id": "lan-with-you","kind": "lan",   "address": "192.168.1.100:25565", "version": "1.21.4",
      "auth": "offline",  "note": "你用自己的号进来一起玩" },
    { "id": "friend-smp", "kind": "remote", "address": "smp.example.com:25565", "version": "1.21.4",
      "auth": "microsoft", "policy": "guest", "note": "别人的服，权限受限" }
  ]
}
```

```ts
interface WorldProvider {
  list(): WorldEntry[];
  connect(worldId): Promise<WorldSession>;   // 预检版本/模组/白名单 → 连 → 等 spawn
  leave(): Promise<void>;
  status(): { worldId, connected, pos, pingMs };
}
```

**会话（WorldSession）是一次"绑定"**：

```
session = { worldId, botId, joinedAt, permissions, snapshot }
```

- 切换世界 = **换槽**，她的 `id`、记忆、承诺、代数都不变（SPEC-05：身份与槽分家）；
- 掉线重连 = 同一 session 重建，对账后继续（SPEC-03 P-25）；
- `worldId = none` 时，她是纯聊天/写代码状态。

### 3.1 预检（连接前必须做）

| 检查 | 失败时 |
|---|---|
| 版本是否在 bot 支持范围 | 拒绝连接，报"版本不匹配" |
| 是否要求正版登录（online-mode） | 用对应 auth 方式，或拒绝 |
| 白名单 / 封禁 | 记一条 `world_denied`，不重试 |
| 模组要求（如需客户端模组） | 标记 `modded: true`，降级为"不连" |
| 延迟 | 记录 ping，超阈值提示 |

### 3.2 在别人的服里 = 不可信环境

这是新的安全面：**陌生世界里的玩家可以对她说话**（和弹幕一样是 untrusted）。

- 她的动作仍受 SPEC-02 闸门管；
- 在 `policy: guest` 的世界里：**禁止执行代码、禁止改方块超过 N 个、禁止私信**；
- 她的记忆照常写，但**不把陌生人的话写进长期承诺**（除非她明确答应）。

---

## 4. 和你联机：只是"两个玩家"

- 用你的正版账号进同一个服务端；
- 她是另一个玩家（离线名或小号）；
- 架构上**没有任何特殊处理**：她的 bot 依旧是客户端，你的客户端和她是平等的。

唯一要注意的是**世界归属**：如果世界开在你的机器上，那你是服主，她是访客；反过来也一样。

---

## 5. 对现有代码的改动

| 现在 | 改成 |
|---|---|
| `mc-1.21.4/` 里跑一个服务端，bot 写死连 25565 | `worlds.json` + `provider.worlds.mjs`；bot 收 `worldId` 参数 |
| `run.js` 里 `HOST/PORT/VERSION` 是常量 | 从 session 注入 |
| 世界与"她的系统"在同一份启动脚本里 | 世界是独立服务；启动器只负责"连" |
| 开播与否没有显式开关 | `streaming` 已是不变量（SPEC-03 §6），补一个 `/stream start|stop` |

**注意**：这不会改动 Renderer/Outlet/Bridge 一行——它们只看 `streaming` 与场景，不看世界。

---

## 6. 一句话

> **她的身份不属于任何一个世界，世界只是她"此刻连着的服务"。**
> 所以：换服 = 换槽；不开播 = 关投影；联机 = 多一个玩家。三件事互不相干。
