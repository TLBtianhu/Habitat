# 客户端清单与两个维度

> 2026-10-31 · 回答："一共要几个 AI 版客户端？"
> 答案：**4 个业务客户端 + 2 个基础设施适配器**。另外必须把"写模组"和"改自己"分成两个维度。

---

## 1. 四个业务客户端

| 客户端 | 对应人类软件 | 职责 | 位置 |
|---|---|---|---|
| **mc-launcher**（AI 版启动器，类 PCL） | PCL / Prism Launcher | 世界注册表、版本/模组下载、实例与登录、预检 | 注册表在 Windows；**下载/构建在 WSL** |
| **mc**（AI 版游戏客户端） | Minecraft Java | 连接、obs、动作、游戏内聊天 | **WSL** |
| **live**（AI 版直播客户端） | 直播姬 / 弹幕助手 | 读/发弹幕、礼物/SC/关注，热插拔 | **Windows**（随 `streaming` 装卸） |
| **ide**（AI 版 IDE） | VS Code / IDEA | **只写 MC 模组**：需求 → 委托 coding agent → 编译/测试 → 上线 | 编排 Windows；**构建/测试 WSL** |

基础设施适配器（可复用，不算独立业务客户端）：
- `browser`：任意网页（WSL）
- `terminal`：PTY / 文件 / 测试输出（WSL）

---

## 2. 关键：写模组 ≠ 改自己

这是三个不同的东西，**绝不能共用一条通道**：

| 东西 | 谁写 | 在哪写 | 属于哪一层 |
|---|---|---|---|
| **MC 模组**（服务端 NeoForge mod） | 可以委托**其他 AI**（coding agent） | **IDE 客户端** | 客户端层 |
| **行为插件 / 技能**（她的动作、她的技能库） | 她自己或人审 | **AgentLoop 自迭代** | 心智层 |
| **人格 / 提示词 / 宪法** | 只能人改 | 人工编辑 | 不可自改 |

**IDE 客户端里没有 `self.modify`、没有 `agent.*` 能力。** 它只能产出"模组 artifact"，不能产出"行为插件"，更不能动她的人格。

---

## 3. IDE 客户端：vibe coding 是"委托"，不是"自写"

IDE 客户端里的大肥鱼不是程序员，是**甲方/导演**：

```
她提需求（"我要一个能发光的方块"）
   → 委托 coding agent（Claude Code / OpenHands / DSH subagent）
   → 对方在 WSL 里写源码、编译、跑测试
   → 她看 diff、看测试、决定是否进重启窗口
```

**限制只在模组编写**：需求、diff、测试、回滚全部围绕 NeoForge 服务端 mod；不许借机写"让我更会说话"这种插件。

这正好对应你最早的分工提议：**出源码和构建派给不同子代理**——一个负责写，一个负责验。

---

## 4. 两个维度各自的位置

| 维度 | 编排 | 执行 | 产出 |
|---|---|---|---|
| **客户端层：模组** | IDE 客户端（Windows） | WSL（JDK/Gradle/一次性实例） | `mod.jar` → 服务端重启窗口 |
| **心智层：自迭代** | AgentLoop（Windows） | WSL（技能沙箱） | 行为插件 artifact → 蓝绿热更 |

**共用"一次性实例 + 测试门禁 + 可回滚"，但目标、能力清单、许可边界完全不同。**

---

## 5. 一句话

> **IDE 客户端负责"她能做出什么 mod"，AgentLoop 负责"她是谁"。**
> 前者可以外包给其他 AI；后者只能由她自己（在人的边界内）慢慢改。
