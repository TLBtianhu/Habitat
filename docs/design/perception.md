# 感知架构：模型看到的世界，和观众看到的世界

> 2026-10-31 · 回答三个问题：
> ① MC/编程都是事件极多的任务，LLM 到底收到什么？
> ② Worker 全是数据层，那"渲染一帧给视觉"怎么发生？
> ③ AI 看到的世界、能吐的世界，长什么样？

---

## 0. 先分清四个"世界"

| 名字 | 在哪 | 谁消费 | 形态 |
|---|---|---|---|
| **真世界** | Authority + 世界服务端 | 裁决用 | 状态（方块、实体、背包、文件、测试结果） |
| **观测**（observation） | 由"观测编译器"产出 | **模型** | 文本字段 + 事件摘要 + 可选小图 |
| **画面**（frame） | Renderer | **观众** | 高保真像素 + 音频 |
| **意图**（intent） | 模型输出 | 政策段/Worker | 闭集动词 + 参数 + 文本 + 代码提案 |

**关键：观测 ≠ 画面。** 它们都是真世界的投影，但预算、频率、目的完全不同。混为一谈，才会问出"沙箱里没渲染器，模型怎么看"。

---

## 1. 模型收到什么：不是事件流，是"观测帧"

MC 每 tick 产生几十条事件，编程每次都产生成百行输出——**这些都不该进模型**。它们进的是**泵**，模型拿的是**投影**。

### 1.1 三种预算决定一切

| 预算 | 量级 | 含义 |
|---|---|---|
| token | 每轮 500–2000 | 放不下整个背包和全部日志 |
| 延迟 | 0.5–3 s/轮 | 不能等太久，也不能每 tick 问一次 |
| 噪声 | —— | 无关事件会稀释注意力，降低判断质量 |

所以观测是**采样 + 打分 + 摘要**，不是流式转发。

### 1.2 观测帧的结构（v0.1）

```jsonc
{
  "t": "obs", "at": 1730000000, "mode": "play",
  "self":  { "pos": [12,64,-8], "facing": "north", "health": 18, "food": 16, "held": "iron_axe" },
  "task":  { "id": "chop_tree", "step": 2, "of": 3, "progress": 0.4, "blocked": false,
             "blockedReason": null },
  "nearby":{ "radius": 12, "summary": "6 棵橡树；1 个僵尸 8m 西北；东边 6m 有河" },
  "events":[ {"k":"damage","from":"zombie","hp":18},
             {"k":"chat","who":"小鱼干","text":"你后面有僵尸"} ],
  "lastFail": null,
  "view":  { "kind": "topdown", "w": 320, "h": 180, "img": "<base64 jpeg>" }   // 可选
}
```

编码模式换一套字段：

```jsonc
{
  "t": "obs", "mode": "code",
  "file": "skills/chop-tree/index.mjs",
  "cursor": { "line": 42, "col": 8 },
  "diffSinceLast": "+ if (block.name === 'oak_log') await dig(block)",
  "test": { "status": "failed", "name": "chops 3 logs", "error": "TypeError: dig is not a function" },
  "recentEdits": ["+12 -3", "+0 -0"]
}
```

**同一份真世界，两种观测。** 观测是按相位定制的投影，不是通用 dump。

### 1.3 频率：不是每帧，是"该看的时候"

| 触发 | 何时 | 频率 |
|---|---|---|
| 定时 | 长任务推进中 | 0.2–1 Hz |
| 事件驱动 | 受伤、被点名、任务失败、卡住 | 立即 |
| 请求驱动 | 模型主动"再看一眼" | 按需 |
| 静默 | 没事发生 | 不喂（省 token） |

**事件负责"叫醒"，观测负责"说明"。** 中间隔着一层注意力闸门（SPEC-01 §7 的批次 + 打分）。

## 2. 那"渲染一帧给视觉"怎么发生？

答案是：**Worker 不渲染。渲染器本来就在出口，它同时产两种图。**

```
真世界 ──► Renderer ──┬── profile=present  ──► 1280×720@30  → 观众
                      └── profile=perceive ──► 320×180@1–2 → 模型
```

同一个渲染器、同一套场景，两个预算档：

| | present（给观众） | perceive（给模型） |
|---|---|---|
| 分辨率 | 1280×720 | 320×180（或 480×270） |
| 帧率 | 30 | 0.5–2 |
| 后处理 | 光晕/阴影/角色 | 关掉，只留几何与色块 |
| 用途 | 好看 | 判断（对齐、朝向、有没有路） |
| 成本 | 高 | 极低（一张图 ≈ 200–400 vision token） |

**这就是为什么 Worker 不需要 GPU**：它的职责是"产生状态"，不是"产生画面"。眼睛和嘴巴都在出口。

### 2.1 但像素是贵的，能用符号就不给图

规则：**能用符号判断的，不给图。**

| 任务 | 该给什么 |
|---|---|
| 砍够 16 个木头 | 结构化：背包计数 + 附近树的数量 |
| 房子盖歪了吗 | **图**（这是空间判断，符号说不清） |
| 这个报错为什么 | 文本：错误栈 + diff |
| 合成表对不对 | 结构化：配方匹配结果 |

所以 `view` 字段是**可选**的，由任务类型决定，不是每轮都带。

## 3. AI 看到的世界 vs 能吐的世界

### 3.1 她看到的（perception）

- **只能看到观测帧**，永远看不到"真世界"；
- 观测帧由我们编译——**我们看到什么，她才能看到什么**；
- 所以"观测编译器"是一等公民：它决定什么是显著的（salience），做错了她会"看不见僵尸"。

### 3.2 她能吐的（action）

闭集，刻意很窄：

```ts
type Intent =
  | { k: 'verb', v: 'walk'|'dig'|'place'|'look'|'say'|'switch_scene'|'play_media'|'idle', args }
  | { k: 'say', text: TrustedText }          // 说话
  | { k: 'code', artifact: ArtifactDraft }   // 写插件（只在 CODE 相位）
  | { k: 'wait', ms }                        // 等
```

**她不能吐**：像素、任意 shell、网络请求、文件路径、新动词。
这不是能力不足，是边界（SPEC-02 §5：`ArgValue` 里根本没有 Path/Url 类型）。

### 3.3 两个世界的接口就是"观测编译器 + 意图闸门"

```
真世界 ──[观测编译器]──► 观测 ──► 模型 ──► 意图 ──[政策段]──► 命令 ──► Worker
             ▲                                              │
             └──────────── 结果（成功/失败/变化）─────────────┘
```

**模型不直接连世界，它连的是这两个编译器。** 这两个编译器写得好不好，决定她"聪不聪明"，跟模型大小无关。

---

## 4. 对架构的推论

1. **新增一个组件**：`observer`（观测编译器），住在 Authority，输入真世界投影，输出观测帧。它有自己的规格（待写 `SPEC-07`）。
2. **Renderer 加一个 profile**：`present` / `perceive`，同一份场景代码两个预算。
3. **L1 链路要分清两类数据**：`state`（给渲染与观测）与 `frame`（只给观众）。现在两者混在一起，需要拆开。
4. **Worker 永远不需要视觉输出**——它没有眼睛，眼睛在出口。

---

## 5. 一句话

> **她看见的是"我们编译过的世界"，她能吐出的是"我们允许的动词"。**
> 中间那层编译器，就是这个 agent 的真正"感官"；画面只是给观众的那一份投影。
