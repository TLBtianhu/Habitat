# ADR-003 生命周期单位与自主下播

> 状态：**已定**（2026-10-31）· 影响面：相位机、人工介入频率、存档结构
> 触发问题：她能不能自主下播？——这其实是在问"系统的生命周期以什么为单位"。

---

## 1. 三种候选模型

| 模型 | 开播/下播 = | 记忆与承诺 | 观众感知 |
|---|---|---|---|
| **A 场次即生命** | 出生 / 死亡 | 每场重置（或仅存档） | 每次都是"新的一期节目" |
| **B 生涯跨场次** | 醒来 / 睡去 | 连续，跨场可查 | "她昨天答应我的事还记得" |
| **C 世界持久，她只是参与者** | 上线 / 下线 | 世界存档才是真源，她记的是"我去过哪" | "那个世界一直在，她只是今天来了" |

三个模型不是互斥的，可以叠。但**只能有一个是真源**。

## 2. 决定：B 为主，C 为容器

- **L1 场次**（分钟~小时）：一次开播到下播。可自主结束。
- **L2 日程**（天）：一个播出窗口。人在窗口外不介入。
- **L3 生涯**（跨天）：记忆、代数、承诺账本、世界存档**连续**。人只看报告。

**L3 是真源，L1 是投影。** 直播、录播、切片是同一个 L3 的三种出口（对应 A3）。

**推论**：现在的 `IDLE` 是"在播间隙"，不够用。需要新增第七相位 **`OFFLINE`**——不播，但她还活着：整理记忆、核对承诺、准备下一场。它与 `IDLE` 的区别是：`IDLE` 里她还在场（待机画面），`OFFLINE` 里观众看不见她。

## 3. 下播必须是谓词，不是情绪

自主下播最容易变成"逃避困难"。所以把条件写成**可验证的谓词**：

```
canEnd = promisesCleared()                 // 承诺清空，或已明确结转
       ∧ duration >= MIN (20min)           // 不许一开播就走
       ∧ (goalDone() ∨ idleDensity < θ 持续 15min ∨ duration >= MAX (6h))
       ∧ NOT blockingOnHardTask()          // 不许因为难而走
```

- **不许因为难而走**：如果当前任务卡住，她**必须**说明卡在哪、下次怎么继续，然后才能下播。卡住是内容，跑掉不是。
- **上限是保护**：6 小时硬上限保护机器与观众预期，不是"她累了"。
- **下限是诚意**：20 分钟内不许自主下播，防止"开播即走"刷存在感。

## 4. 人工触发：四类，一个预算

| 类型 | 何时 | 稳态频率 | 能否省 |
|---|---|---|---|
| **点火** | 首次部署、故障恢复、长假后 | ≤ 1 次/周 | 稳定后应趋近 0 |
| **批准** | L3/L4 操作（改部署、装原生插件） | 0–3 次/场 | 不可省（安全底线） |
| **接管** | 异常、越界、她要碰不该碰的 | 目标 0 次/场 | 不可省 |
| **复盘** | 每周一次，看交接与承诺 | 1 次/周 | 可省（看报告即可） |

**预算：稳定期人类介入 ≤ 3 次/周。** 超过这个数，说明系统在"假装自主"——不是她不会自己活，是我们在替她活。

这个预算同时是一个**验收指标**：连续 5 场没有人工点火，才算"真的能自己开播"。

## 5. 场次交接：让生命周期真的变长的那个东西

下播前**必须**写 `session.json`：

```json
{
  "sessionId": "…",
  "startedAt": "…", "endedAt": "…",
  "durationMin": 187,
  "done": ["把房子盖到第二层", "给 3 个观众回了私信"],
  "promises": [
    {"to": "actor:8842", "what": "下次带你看矿洞", "dueBy": "next-session"}
  ],
  "unfinished": [{"task": "挖到钻石层", "why": "镐子坏了", "nextStep": "先做铁镐"}],
  "mood": "…",            // 只作叙事，不作状态
  "generation": 37
}
```

**规则**：
1. 写不出 `session.json` → **不许进入 `ENDING`**（没有交接就没有下一场）；
2. 下一场开场**必须**读它，并**至少兑现一件**承诺；
3. 未兑现承诺超过 2 场 → 状态角标红标，且她**必须**在直播里说明；
4. 承诺账本是 append-only，**严禁**删除（删了就等于没答应过）。

## 6. 后果

**好的**
- "她记得"变成可验证的事实，不是提示词营造的幻觉；
- 自主性有了度量（人工介入频率），不靠感觉；
- 卡住也能下播，但必须在镜头前说清——把"逃避"转成"叙事"。

**坏的**
- 多一个相位、多一套存档与对账逻辑；
- 她可能为了兑现承诺硬撑（用上限兜底）；
- 承诺账本会越积越多，需要"过期/失效"规则（建议：超过 7 天未兑现自动转入"欠账"并降级处理）。

## 7. 裁定（2026-10-31 全部采纳）

1. **接受 L3 为真源、直播为投影** → 相位机新增 `OFFLINE`（七相位），`IDLE` 只保留"在播间隙"语义；
2. **人工介入预算 ≤ 3 次/周** 成立 → 自动点火与自愈进 P1 范围（因此 P1 增加约一周）；
3. **承诺失效期 7 天** 成立 → 超期转入"欠账"并降级处理，账本本身只增不删。
