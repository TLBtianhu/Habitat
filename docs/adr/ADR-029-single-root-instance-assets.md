# ADR-029: 单根目录实例与资产边界

日期：2026-11-04
状态：Accepted（生产迁移允许；必须先备份、可回滚，不启用 MC autoStart）

## 决策

Habitat 的每个安装实例只有一个根目录。解耦通过子目录完成，不通过 `/etc`、`/var/lib`、用户 home 或系统级语言环境分散完成。

生产实例的目标根为 `/opt/habitat`；独立用户实例继续使用各自已选择的根目录。开发和生产实例不能共享配置、世界、缓存、进程或激活状态。

```text
<实例根>/
  app/                 可整体替换的应用与基础资源
  runtime/             完整、独立、可重定位的语言环境和程序运行时
  data/                世界、Episode、社交记忆、备份、日志和缓存
  config/              设置与秘密
  state/               启停、激活、迁移和恢复状态
  tmp/                 可精确清理的安装/验收暂存区
```

`app/runtime` 中随源码分发的脚本和锁文件属于应用本体；外部 Node、Java、Python、MC 客户端及其缓存属于根级 `runtime`，两者不混用。

## 资产规则

- `app`：安装/修复时整包替换，升级失败恢复旧版本。
- `runtime`：每个语言或环境是一个完整单文件夹，按版本和 SHA256 管理；只在真实自检后激活。
- `data`：默认保留，升级不得覆盖世界、Episode、记忆或备份。
- `config`：默认保留，秘密不进入日志、状态 API、运行时包或公开文档。
- `state`：可以恢复重建，保存 applied/degraded/recovery 等状态，不作为用户数据。
- `tmp`：只用于暂存，按精确路径清理，不能演变为第二数据目录。

## 禁止的外部依赖

正式实例不得依赖系统 Java/Python/Node、全局 npm/pip、`~/.minecraft`、`~/.local/share/headlessmc`、开发机绝对路径或根目录外的共享缓存。

`JAVA_HOME`、`PYTHONHOME`、`HOME`、`XDG_*`、运行时 `PATH` 和激活配置必须指向当前实例根内部。环境目录必须能够整体移动、替换、备份和删除。共享 MC 缓存使用根内相对链接，移动根目录后仍需通过链接和解释器自检。

## 生产迁移映射

旧生产部署的拆分目录按以下方式收口，先复制/校验再切换引用，不直接删除旧数据：

| 旧位置 | 新位置 |
| --- | --- |
| `/opt/habitat/app` | 保持为 `/opt/habitat/app` |
| `/var/lib/habitat` | `/opt/habitat/data` |
| `/etc/habitat` | `/opt/habitat/config` |
| `/home/<user>/opt/node22` | `/opt/habitat/runtime/node22` |
| `/home/<user>/opt/jdk25`、`jdk21` | `/opt/habitat/runtime/java/...` |
| HeadlessMC 外部缓存 | `/opt/habitat/runtime/mc-client/cache` 或实例数据内的明确缓存目录 |

旧目录只在迁移验证和回滚窗口内保留。切换前必须在 `state` 保存配置、数据和服务定义备份及 SHA256；切换后验证 QQ、控制面、Episode、文件权限和真实写入路径，再决定清理。

## 升级与恢复

所有运行时资产遵循：下载/读取 → 校验 → 暂存 → 重定位 → 真实自检 → 原子激活 → 健康检查。自检失败不得写激活标记，旧版本必须仍可启动。

世界恢复遵循：停止客户端和世界 → 校验备份 → 暂存展开 → 原子替换 → 重启并验证 RPC → 失败恢复原世界。不得把“有备份”当成“已经能恢复”。

## 验收

- 非管理员首装与自定义根目录可用。
- 整个根目录移动后，经重定位和自检仍可启动。
- 连续升级/验收不重复制造大型 JDK/assets 副本。
- 默认卸载只处理程序，保留配置、运行时、世界和备份；全选必须再次确认。
- QQ 在迁移后保持可用；不自动启动 MC、公开端口或直播。
- 测试失败不能留下失控 Java 进程或模糊的删除操作。
