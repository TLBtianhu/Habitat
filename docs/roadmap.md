# Habitat 推进规划与调研清单

> 2026-10-31 · 原则：**先让单个实例稳定活着，再接原生客户端，最后做长期心智与社区化。**

## 当前基线（已具备）

- WSL 原生 JDK / MC 服务端 / bot / obs；
- 第一视角与 CODE 场景、HLS/RTMP 出口；
- 模式机、技能蓝绿回滚、规则 AgentLoop；
- 分发包与一键验收。

---

## M1：地基收敛（1–2 周）

### 交付

1. **Display Server MVP**：把 stage + pipeline 收敛成独立服务，支持 `SceneDescriptor`、`ViewEvent`、surface 合成、待机卡；
2. **Identity Hub MVP**：manifest → 统一绑定页 → 凭证库 → scope token；
3. **运维收敛**：systemd/启动脚本、健康总览、日志规范、24h soak。

### 调研

- DSH Linux 部署方式、MCP 注册/权限模型、子代理与技能加载机制；
- 凭证存储：libsecret / keytar / 加密文件，哪套最适合无头服务器；
- Bilibili 扫码登录、Microsoft device-code 的刷新与失效处理；
- Display 合成性能：headless Chrome 与原生 compositor 的成本对比。

### 验收

- 新增一个客户端只加 manifest，不改绑定页；
- 两个 surface 可同时合成，Outlet 可切 HLS/RTMP；
- 断电重启后身份与世界会话可恢复。

---

## M2：原生 QQ 与 B 站客户端（2–3 周）

### 交付

1. **QQ 客户端**：独立协议后端 + OneBot，支持群/私聊读写、图片、事件回推；
2. **B 站客户端**：搜索/视频信息/评论读取、直播间弹幕 WebSocket；
3. **QQ 场景**：聊天面板进入 Display Server，支持直播展示 QQ 互动。

### 调研

- QQ 后端：go-cqhttp / Lagrange.Core / NapCat 的部署方式、维护状态、协议风险；
- OneBot 11/12 消息段、事件模型、图片与戳一戳；
- QQ 屏幕共享是否可用协议实现，不能则走 Display Server 虚拟屏幕；
- B 站公开 API 与弹幕协议、限频与封控；
- 消息去重、回环防护、敏感操作审计。

### 验收

- 不出现 QQ 窗口，不依赖注入；
- 群里 @她 能触发 AgentLoop，回复可见；
- B 站弹幕进入统一事件队列，直播画面可显示。

---

## M3：真实心智接入（2–4 周）

### 交付

1. **LLM AgentLoop**：替换规则脑，观测 → 决策 → 闭集动作；
2. **记忆与承诺**：长期记忆、session 交接、承诺账本、上下文压缩；
3. **子代理工作流**：研究/写模组/测试可并行，世界动作仍串行。

### 调研

- 模型提供方与成本、速率限制、工具调用格式；
- 长生命周期记忆：摘要、检索、遗忘、承诺过期；
- 上下文压缩策略与回放一致性；
- 子代理权限隔离：只读研究 vs 可写世界。

### 验收

- 她能根据 QQ/MC/直播事件自主决策；
- CODE 不碰世界，PLAY 不碰代码；
- 同一事件日志回放结果一致。

---

## M4：模组生产线（2–3 周）

### 交付

1. **IDE 客户端**：需求 → 委托 coding agent → 构建 → 测试 → 上线；
2. **模组 artifact**：manifest、测试报告、回滚、服务端重启窗口；
3. **直播展示**：IDE 场景与模组 diff/测试状态上屏。

### 调研

- NeoForge 1.21.4 API 与模板工程；
- 一次性实例的构建/测试/存档隔离；
- 模组兼容性与服务端重启成本；
- 模组签名、许可与依赖审查。

### 验收

- 她能做出一个最小模组并上线；
- 构建失败不切换，测试失败可回滚；
- 模组线与行为插件线互不越界。

---

## M5：社区化与部署（持续）

### 交付

- Linux 服务器长驻部署、统一身份绑定页、公开文档；
- 多场景复合直播、QQ 屏幕共享、观众点播；
- Android/Termux 可行性验证（可选）。

### 调研

- 服务器 GPU/无头渲染成本与运维；
- 公开社区中的内容审核、限频、反滥用；
- Android 上 DSH/客户端的可移植性；
- WebRTC 低延迟互动是否值得替代 HLS。

---

## 优先调研 Top 8

1. **QQ 协议后端**：go-cqhttp / Lagrange / NapCat 的可用性与风险；
2. **DSH Linux + MCP**：如何注册客户端、隔离工具面、接子代理；
3. **身份与 OAuth**：QQ/B站扫码、Microsoft device-code、凭证存储；
4. **Display Server 合成**：surface、布局、渲染后端与性能；
5. **B 站 API 与弹幕**：读取、评论、直播间事件、限频；
6. **MC 动作栈**：pathfinder、挖掘、放置、合成、死亡恢复；
7. **长期记忆**：压缩、检索、承诺账本、session 交接；
8. **NeoForge 生产线**：构建、测试、回滚、服务端重启窗口。

## 明确不做

- 不再做“注入现有 QQ 客户端”的路线；
- 不把项目绑定到某个群、某个 MC 服或某个直播平台；
- 不把“会开播”当成项目的核心价值；
- 不在地基未稳时追多平台同时开播。
